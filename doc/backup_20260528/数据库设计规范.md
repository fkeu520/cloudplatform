**版本：** v1.0  
**日期：** 2026-05-15  
**适用范围：** MySQL 8.0+ 数据库设计

## 一、命名规范

### 1.1 数据库对象命名

| 对象类型 | 命名规范 | 正例 | 反例 |
|---------|---------|------|------|
| **数据库** | 小写，下划线 | `cloudhub_platform` | `CloudhubPlatform` |
| **表** | `t_模块_业务`，小写 | `t_user` `t_order_item` | `user` `T_User` |
| **字段** | 小写，下划线 | `user_name` `create_time` | `userName` `UserName` |
| **索引** | `idx_表名_字段`，`uk_表名_字段` | `idx_user_name` `uk_user_email` | `index1` `Index_Name` |
| **外键** | `fk_从表_主表` | `fk_order_user` | `fk1` |
| **视图** | `v_名称` | `v_user_detail` | `userView` |
| **存储过程** | `sp_名称` | `sp_order_statistics` | `proc1` |
| **触发器** | `trg_表名_操作` | `trg_user_insert` | `trigger1` |

### 1.2 表名设计

```sql
-- ✅ 模块前缀 + 业务名称
t_user                  -- 用户模块-用户表
t_user_role            -- 用户模块-用户角色关联表
t_org                  -- 组织模块-组织表
t_org_structure        -- 组织模块-组织结构表
t_order                -- 订单模块-订单表
t_order_item           -- 订单模块-订单明细表
t_config_system        -- 配置模块-系统配置表
```

## 二、字段设计规范

### 2.1 必备字段

```sql
CREATE TABLE t_user (
    -- 主键（必须）
    id              BIGINT UNSIGNED NOT NULL PRIMARY KEY COMMENT '主键ID',
    
    -- 业务字段
    user_name       VARCHAR(50) NOT NULL COMMENT '用户名',
    
    -- 时间字段（必须）
    create_time     DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    update_time     DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    
    -- 逻辑删除（必须）
    is_deleted      TINYINT NOT NULL DEFAULT 0 COMMENT '是否删除：0-否，1-是',
    
    -- 租户ID（多租户场景必须）
    tenant_id       BIGINT NOT NULL DEFAULT 0 COMMENT '租户ID',
    
    -- 创建/更新人（推荐）
    create_by       BIGINT COMMENT '创建人ID',
    update_by       BIGINT COMMENT '更新人ID',
    
    -- 乐观锁（并发场景推荐）
    version         INT NOT NULL DEFAULT 0 COMMENT '乐观锁版本号',
    
    -- 排序（列表展示推荐）
    sort_order      INT NOT NULL DEFAULT 0 COMMENT '排序号',
    
    -- 扩展字段（JSON格式，推荐）
    ext_json        JSON COMMENT '扩展字段',
    
    -- 备注
    remark          VARCHAR(500) COMMENT '备注'
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户表';
```

### 2.2 字段类型选择

| 数据类型 | 适用场景 | 示例 |
|---------|---------|------|
| `BIGINT` | 主键ID、外键、大整数 | `id`, `user_id` |
| `INT` | 状态码、计数、小整数 | `status`, `age`, `sort_order` |
| `TINYINT` | 布尔值、小范围枚举 | `is_deleted`, `gender` |
| `VARCHAR(n)` | 短文本（n根据实际定） | `name`(50), `email`(100), `phone`(20) |
| `TEXT` | 长文本（<= 65535字符） | `description`, `content` |
| `LONGTEXT` | 超长文本 | `article_content` |
| `DECIMAL(16,2)` | 金额（精确计算） | `amount`, `price` |
| `DATETIME(3)` | 日期时间（含毫秒） | `create_time` |
| `DATE` | 仅日期 | `birthday` |
| `JSON` | JSON格式数据 | `ext_json`, `config` |
| `BLOB` | 二进制数据（不推荐） | 尽量用文件存储，存URL |

### 2.3 字段设计禁忌

```sql
-- ❌ 禁止使用 NULL 表示业务含义
is_active TINYINT NULL;  -- 错误：NULL 和 0 混淆
is_active TINYINT NOT NULL DEFAULT 1;  -- ✅ 正确

-- ❌ 禁止使用外键约束（影响性能，应用层保证）
CONSTRAINT fk_order_user FOREIGN KEY (user_id) REFERENCES t_user(id);  -- 错误
-- 使用应用层保证数据一致性  -- ✅ 正确

-- ❌ 禁止存储图片/BLOB大字段
avatar BLOB;  -- 错误
avatar VARCHAR(255);  -- ✅ 正确，存储文件URL

-- ❌ 禁止使用 TEXT/BLOB 类型建索引
INDEX idx_content (content);  -- 错误
-- 如需搜索，使用 Elasticsearch  -- ✅ 正确
```

## 三、索引设计规范

### 3.1 索引原则

```sql
-- ✅ 主键索引
PRIMARY KEY (id)

-- ✅ 唯一索引（业务唯一）
UNIQUE KEY uk_user_email (email)
UNIQUE KEY uk_org_code (tenant_id, org_code)  -- 租户内唯一

-- ✅ 普通索引（查询条件）
KEY idx_user_status (status)
KEY idx_user_dept (dept_id, status)

-- ✅ 组合索引（最左前缀原则）
KEY idx_order_user_time (user_id, create_time)
-- 支持：WHERE user_id = ? / WHERE user_id = ? AND create_time = ?
-- 不支持：WHERE create_time = ?

-- ✅ 覆盖索引（查询字段都在索引中）
KEY idx_order_status_time (status, create_time)
-- SELECT status, create_time FROM t_order WHERE status = 1

-- ❌ 避免冗余索引
KEY idx_user_name (user_name)
KEY idx_user_name_age (user_name, age)  -- idx_user_name 冗余
```

### 3.2 索引数量控制

- 单表索引数不超过 5 个
- 单个索引字段数不超过 5 个
- 索引字段总长度不超过 1000 字节
- 频繁更新的字段慎建索引

## 四、SQL 编写规范

### 4.1 查询语句

```sql
-- ✅ SELECT 指定字段，禁止 *
SELECT id, user_name, email, status
FROM t_user
WHERE is_deleted = 0
  AND status = 1
ORDER BY create_time DESC
LIMIT 20 OFFSET 0;

-- ❌ 禁止 SELECT *
SELECT * FROM t_user;  -- 错误

-- ✅ 分页查询
SELECT id, user_name
FROM t_user
WHERE is_deleted = 0
ORDER BY create_time DESC
LIMIT 20 OFFSET 0;  -- 第1页

-- ✅ 批量查询（IN 控制数量）
SELECT id, user_name
FROM t_user
WHERE id IN (1, 2, 3, ..., 100)  -- IN 数量不超过 1000
  AND is_deleted = 0;

-- ✅ 使用 EXPLAIN 分析执行计划
EXPLAIN SELECT * FROM t_user WHERE email = 'test@example.com';
```

### 4.2 更新语句

```sql
-- ✅ 带 WHERE 条件，防止全表更新
UPDATE t_user
SET status = 0,
    update_time = NOW()
WHERE id = 1
  AND is_deleted = 0;

-- ✅ 乐观锁更新
UPDATE t_user
SET balance = balance - 100,
    version = version + 1
WHERE id = 1
  AND version = 5;  -- 版本号校验
-- 影响行数为0表示冲突，需重试

-- ❌ 禁止无 WHERE 的 UPDATE/DELETE
UPDATE t_user SET status = 0;  -- 危险！会更新全表
```

### 4.3 批量操作

```sql
-- ✅ 批量插入
INSERT INTO t_user (id, user_name, email, status)
VALUES
    (1, '张三', 'zs@example.com', 1),
    (2, '李四', 'ls@example.com', 1),
    (3, '王五', 'ww@example.com', 1);
-- 每批不超过 1000 条

-- ✅ 批量更新（使用 CASE）
UPDATE t_user
SET status = CASE id
    WHEN 1 THEN 0
    WHEN 2 THEN 1
    WHEN 3 THEN 0
END
WHERE id IN (1, 2, 3);

-- ✅ 批量删除（软删除）
UPDATE t_user
SET is_deleted = 1,
    update_time = NOW()
WHERE id IN (1, 2, 3)
  AND is_deleted = 0;
```

## 五、分库分表规范

### 5.1 拆分原则

| 拆分方式 | 适用场景 | 分片键 |
|---------|---------|--------|
| **垂直拆分** | 字段过多（>50个）、访问频率差异大 | 按业务模块拆分 |
| **水平拆分** | 数据量过大（单表>500万）、并发高 | user_id, order_id |

### 5.2 分片键选择

```sql
-- ✅ 用户相关表：按 user_id 分片
-- 分片算法：user_id % 16

-- ✅ 订单相关表：按 order_id 分片
-- 使用雪花算法生成 order_id，内置时间戳和机器ID

-- ✅ 日志类表：按时间分片
-- t_operation_log_202401, t_operation_log_202402
```

## 六、安全规范

### 6.1 数据安全

```sql
-- ✅ 敏感字段加密存储
ALTER TABLE t_user ADD COLUMN id_card_enc VARCHAR(256);
-- 使用 AES_ENCRYPT 加密，应用层解密

-- ✅ 密码哈希存储
password_hash VARCHAR(256) NOT NULL;  -- BCrypt 哈希

-- ❌ 禁止明文存储
password VARCHAR(50);  -- 错误
```

### 6.2 权限控制

```sql
-- ✅ 应用账号最小权限
-- 只授予必需的权限：SELECT, INSERT, UPDATE, DELETE
-- 禁止：DROP, TRUNCATE, GRANT

-- ✅ 不同环境使用不同账号
-- dev 环境：cloudhub_dev
-- test 环境：cloudhub_test
-- prod 环境：cloudhub_prod（限制IP）
```
