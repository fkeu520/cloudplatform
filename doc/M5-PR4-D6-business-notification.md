### 1.2 正文

```
各位同事:

云枢中台已完成 M5 PR4 数据权限写保护灰度发布, 涉及所有后台业务 (用户/角色/部门/岗位/字典/参数)。

## 核心变更
- **范围**: 平台用户、角色、部门、岗位、字典、参数配置 等模块
- **影响**: scope=2/3/4/5 的用户, **写操作将受 data_scope 限制** (按部门隔离)
- **生效时间**: 2026-06-15 (D+7) 灰度切换

## 5 种 data_scope 说明

| scope | 含义 | SQL 效果 | 典型角色 |
|-------|------|---------|----------|
| 1 | 全部 | 不加条件 | 超级管理员 |
| 2 | 本部门 | WHERE dept_id = 本部门 | 部门主管 |
| 3 | 本部门及下级 | WHERE dept_id IN (子部门) | 区域经理 |
| 4 | 本人 | WHERE user_id = 本人 | 普通员工 |
| 5 | 自定义 | WHERE dept_id IN (custom) | 跨部门专员 |

## 实际影响 (举例)

- **HR 小王 (scope=2 本部门)**: 修改市场部用户信息 → 系统拒绝 (dept_id 不匹配)
- **运营专员 (scope=3 本部门及下级)**: 删除销售 1 组下某员工 → 允许 (dept_id 匹配)
- **市场部总监 (scope=2)**: 删除自己部门外的岗位 → 系统拒绝

## 验证方法

1. 测试环境: http://localhost:8080 (admin/123456)
2. 切换为 scope=2/3/4 角色
3. 尝试跨部门操作 → 预期被拒绝
4. 详细 e2e 验证脚本: `scripts/ci/m5-pr4-d4-e2e-mysql.sh`

## 回退预案

若出现误判, 紧急回退 (5 分钟生效):
- 设置 `PLATFORM_DATA_SCOPE_UPGRADE_WRITE_STRICT=false` 环境变量
- 重启受影响服务
- 联系平台架构组

## Q&A

Q: admin 账号受影响吗?
A: admin 是 scope=1 (全部), 不受影响, 仅审计 scope=2/3/4/5 用户

Q: 我是 scope=2 主管, 改不了下属部门的数据?
A: 跨部门操作需先申请跨部门权限 (scope=5) 或通过 admin 调整

Q: 历史数据有影响吗?
A: 不影响, 数据隔离只影响后续新写操作

更多问题请回复本邮件或加入钉钉群 (xxxxx) 咨询
```

## 2. 培训材料 (用户文档)

### 2.1 角色 (scope) 速查表

| 业务场景 | 推荐 scope | 申请方式 |
|---------|-----------|----------|
| 平台管理员 (运营) | 1 (全部) | 系统默认 |
| 部门主管 | 2 (本部门) | 申请后管理员配置 |
| 区域/分公司负责人 | 3 (本部门及下级) | 申请后管理员配置 |
| 普通员工 (查自己) | 4 (本人) | 系统默认 |
| 跨部门专员 (审批) | 5 (自定义) | 申请后管理员配置 deptIds |

### 2.2 操作示例

#### 示例 1: 部门主管修改下属信息 (允许)

```
1. 登录: 账号 zhangsan, scope=2
2. 部门: 技术部 (dept_id=100)
3. 操作: 修改技术部员工 lisi 的手机号
4. 结果: ✓ 成功 (dept_id 匹配)
```

#### 示例 2: 部门主管修改跨部门信息 (拒绝)

```
1. 登录: 账号 zhangsan, scope=2, dept=技术部
2. 操作: 修改市场部员工 wangwu 的手机号
3. 结果: ✗ 失败 (返回 "用户不存在", 实际数据未被修改)
4. 原因: 读路径已被 dept_id 过滤, 看不到 wangwu
```

#### 示例 3: 超级管理员 (scope=1) 不受影响

```
1. 登录: 账号 admin, scope=1
2. 操作: 修改任意用户/角色/部门
3. 结果: ✓ 全部成功
```

### 2.3 常见问题 (FAQ)

**Q1: 为什么我修改某员工失败, 但查得到这个员工?**
A: 该员工的 dept_id 可能在您有读权限的子部门内, 但不在您有写权限的范围内。请联系管理员调整您的 scope。

**Q2: scope=2 和 scope=3 区别是什么?**
A: scope=2 只能改本部门; scope=3 可改本部门 + 下级子部门。

**Q3: 我是部门主管, 怎么申请跨部门审批权限?**
A: 申请工单到平台架构组, 提供: 申请理由、目标部门列表 (deptIds)、有效期。

**Q4: 紧急情况下需要修改数据怎么办?**
A: 联系 admin 账号操作, 或在钉钉群申请临时提权。
