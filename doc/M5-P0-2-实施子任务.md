## 一、目标

为角色增加**行级数据权限**，区分同角色不同数据范围（如"销售"角色，经理看本部门，员工看本人）。

**5 种 data_scope**:

| 值 | 含义 | SQL 效果 |
|----|------|---------|
| 1 | 全部 | 不加条件 |
| 2 | 本部门 | `WHERE dept_id = ?` |
| 3 | 本部门及下级 | `WHERE dept_id IN (子部门)` |
| 4 | 本人 | `WHERE user_id = ?` |
| 5 | 自定义 | `WHERE dept_id IN (custom_dept_ids)` |

**多角色合并策略** (待用户拍板): **取最严格** (scope 值大者) / **取并集** / **主角色优先**

### 3.2 @DataScope 注解扩展

**当前**: 已存在
**建议扩展**: 加 `deptAlias` / `userAlias` 参数 (支持复杂 join 场景)

```java
@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.METHOD)
public @interface DataScope {
    /**
     * 部门表别名 (如 "d", "dept")
     * SQL: WHERE {deptAlias}.id = ?
     */
    String deptAlias() default "";

    /**
     * 用户表别名 (如 "u", "user")
     * SQL: WHERE {userAlias}.id = ?
     */
    String userAlias() default "";
}
```

### 3.3 DataScopeAspect 完整实现 (重写当前 22 行桩)

**核心逻辑**:

```java
@Before("@annotation(dataScope)")
public void doBefore(JoinPoint point, DataScope dataScope) {
    Long userId = TenantContextHolder.getUserId();
    if (userId == null) return;

    // 1. 查用户的所有 role + data_scope + dept_id
    List<UserRoleDataScope> scopes = userRoleMapper.selectDataScopesByUserId(userId);

    // 2. 合并 data_scope (取最严格)
    int maxScope = scopes.stream()
        .map(UserRoleDataScope::getDataScope)
        .filter(Objects::nonNull)
        .max(Integer::compare)
        .orElse(1);

    // 3. 拼 SQL 条件, 写入 ThreadLocal
    String sqlFragment = buildSqlFragment(maxScope, scopes, dataScope);
    DataScopeContextHolder.set(sqlFragment);
}

private String buildSqlFragment(int scope, List<UserRoleDataScope> scopes, DataScope dataScope) {
    switch (scope) {
        case 1: return "";  // 全部, 不加条件
        case 2: return String.format(" AND %s.dept_id = %d",
            dataScope.deptAlias(), currentUserDeptId);
        case 3: return String.format(" AND %s.dept_id IN (%s)",
            dataScope.deptAlias(), childDeptIds);  // 子部门递归
        case 4: return String.format(" AND %s.id = %d",
            dataScope.userAlias(), currentUserId);
        case 5: return String.format(" AND %s.dept_id IN (%s)",
            dataScope.deptAlias(), customDeptIds);  // custom_dept_ids
        default: return "";
    }
}
```

### 3.4 MyBatis DataScopeInnerInterceptor (新增, 复杂)

**复用 P0-1 TenantLineInnerInterceptor 模式**, 新增 `DataScopeInnerInterceptor`:
- 读 `DataScopeContextHolder` 拿到 SQL 片段
- 拼到 SQL 末尾

**实现路径**:
```java
interceptor.addInnerInterceptor(new TenantLineInnerInterceptor(...));
interceptor.addInnerInterceptor(new DataScopeInnerInterceptor(...));
interceptor.addInnerInterceptor(new PaginationInnerInterceptor(...));
// ⚠️ 顺序: TenantLine 在前 (过滤), DataScope 在中, Pagination 在后
```

## 四、决策日志 (待用户拍板)

### 4.1 多角色 data_scope 合并策略

| 策略 | 实现 | 优点 | 缺点 |
|------|------|------|------|
| **A. 取最严格** (scope 值大者) | `max(dataScope)` | 安全 (越严格越限) | 误限 (用户应有权限也被限) |
| **B. 取并集** (OR 合并) | `dept_id IN (union)` | 灵活 | 复杂 SQL |
| **C. 主角色优先** | `role.isPrimary = true` | 简单 | 需新增字段 |

**推荐 A** (与 L2 优化"安全优先"一致)。

### 4.2 dept 子树查询 (scope=3)

| 方案 | 实现 | 性能 |
|------|------|------|
| **A. 递归 CTE** (MySQL 8.0+) | `WITH RECURSIVE` | 中 |
| **B. 应用层递归** | Java 递归查 sys_dept | 慢 (N+1) |
| **C. 物化路径** (mpath) | 存 `path = "1/2/3/"`, LIKE 查询 | 快 |

**推荐 A** (MySQL 8.0 已支持, 单 SQL 一次返回)

### 4.3 是否复用 TenantLineInnerInterceptor 模式

**推荐复用**: 同一拦截器链, 模式一致, 维护成本低。

## 五、风险与回滚

### 5.1 风险

| 风险 | 缓解 |
|------|------|
| V22 migration 失败 | ALTER TABLE 幂等 (加 DEFAULT 1 兼容老数据) |
| DataScope 漏注解 | 强制 code review: 所有 list 方法必须有 @DataScope |
| 跨服务调用 dept_id 丢失 | 跨服务调用链 dept_id 显式传 |
| 多角色策略导致误限 | 业务测试覆盖, 默认 scope=1 (最宽松) |

### 5.2 回滚

```sql
-- 回滚 V22
ALTER TABLE sys_role DROP COLUMN data_scope;
ALTER TABLE sys_role DROP COLUMN custom_dept_ids;
```

**代码回滚**: git revert (单 commit)
**运行时回滚**: DataScopeAspect 整体加 `@ConditionalOnProperty(platform.data-scope.enabled, matchIfMissing = true)`, 关闭走 v3.1 行为。
