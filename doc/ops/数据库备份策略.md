## 1. 概述

本文档定义云枢中台数据库备份方案，涵盖 MySQL 8.0、Nacos 配置数据及 ES 索引快照。当前环境为 Docker Compose 单机部署，生产可扩展至主从架构。

### 适用范围

| 数据源 | 存储位置 | 备份方式 |
|--------|---------|---------|
| 业务数据（platform 库） | MySQL 8.0 | mysqldump 逻辑备份 |
| Nacos 配置（platform_nacos 库） | MySQL 8.0 | mysqldump |
| 消息数据（platform_message 库） | MySQL 8.0 | mysqldump |
| ES 日志索引 | Elasticsearch 8.12 | snapshot API |
| MinIO 文件 | MinIO | mc mirror |

## 2. 备份策略（推荐）

### 2.1 全量备份 — 每日

```
时间：凌晨 02:00（业务低峰）
方式：mysqldump 单事务模式
保留：最近 7 天全量
```

### 2.2 增量备份 — 每 30 分钟（生产主从可选）

```
前提：MySQL 主从复制 + binlog
方式：mysqlbinlog 解析 binlog 为 SQL
保留：最近 48 小时增量
```

### 2.3 ES 快照 — 每日

```
时间：凌晨 03:00
方式：注册快照仓库 → create snapshot
保留：最近 3 天（日志类索引 ILM 管理）
```

### 2.4 ES 日志索引 ILM — 1 天自动清理

> **新增 2026-06-04**: 与 docker-compose.yml ELK 接入同步，**业务日志保留 1 天**（节省 70% ES 存储）。

```
策略名称: platform-logs-policy
适用索引: platform-logs-*
滚动周期: 1 天
删除周期: 1 天（rollover 后即删）
分片大小: 1 个主分片 + 0 副本（单节点 ES）
```

**ILM 策略内容**（`docker/elasticsearch/ilm-policy.json`）:

```json
{
  "policy": {
    "phases": {
      "hot": {
        "actions": {
          "rollover": {
            "max_age": "1d"
          }
        }
      },
      "delete": {
        "min_age": "1d",
        "actions": {
          "delete": {}
        }
      }
    }
  }
}
```

**关键决策**:
- **业务日志 1 天保留**（hot phase rollover 1d → delete）
- **审计日志 7 天保留**（sys_oper_log / sys_login_log 在 MySQL，ES 镜像仅作分析）
- 重要事件通过**告警**（未来 P1-4 告警分级）触发后**手动归档**

> **存储节省**（估算 @ 1GB/天日志量）:
> - 1 天 ILM vs 7 天全留: **节省 6GB/天磁盘**
> - 7 天累计: 7GB vs 49GB（节省 86%）
> - 推荐 4C8G 生产: 1GB ES 堆可支撑 **1 周**业务日志滚动

### 2.5 MinIO 文件

```
方式：mc mirror 同步到备份存储
频率：每日
保留：同业务库
```

## 3. 实施操作

### 3.1 Docker 定时全量备份脚本

创建备份脚本和定时任务：

**脚本位置**：`/root/scripts/mysql-backup.sh`

```bash
#!/bin/bash
# ============================================
# MySQL 全量备份 (Docker 环境)
# ============================================
BACKUP_DIR="/data/backup/mysql"
DATE=$(date +%Y%m%d_%H%M%S)
RETENTION_DAYS=7
DB_USER="root"
DB_PASS="root123456"

mkdir -p "${BACKUP_DIR}/${DATE}"

# 逐个库备份
for db in platform platform_nacos platform_message; do
    echo "[$(date)] Backing up ${db}..."
    docker exec platform-mysql mysqldump \
        -u${DB_USER} -p${DB_PASS} \
        --single-transaction \
        --routines \
        --triggers \
        --events \
        "${db}" \
        | gzip > "${BACKUP_DIR}/${DATE}/${db}.sql.gz"
done

# 删除过期备份
find "${BACKUP_DIR}" -maxdepth 1 -type d -mtime +${RETENTION_DAYS} -exec rm -rf {} \;

echo "[$(date)] Backup complete: ${DATE}"
```

**定时任务（crontab）**：
```cron
0 2 * * * bash /root/scripts/mysql-backup.sh >> /var/log/mysql-backup.log 2>&1
```

### 3.2 ES 快照

**注册快照仓库**（一次配置）：
```bash
# 进入容器
docker exec -it platform-elasticsearch bash

# 注册仓库
curl -X PUT "localhost:9200/_snapshot/platform_backup" -H 'Content-Type: application/json' -d'
{
  "type": "fs",
  "settings": {
    "location": "/usr/share/elasticsearch/backup",
    "compress": true
  }
}'
```

**创建快照脚本**：
```bash
#!/bin/bash
DATE=$(date +%Y%m%d)
docker exec platform-elasticsearch curl -X PUT \
  "localhost:9200/_snapshot/platform_backup/snapshot_${DATE}?wait_for_completion=true"

# 删除 3 天前快照
OLD_DATE=$(date -d '-3 days' +%Y%m%d)
docker exec platform-elasticsearch curl -X DELETE \
  "localhost:9200/_snapshot/platform_backup/snapshot_${OLD_DATE}"
```

### 3.3 MinIO 文件备份

```bash
# 安装 mc 客户端
docker run --rm -it --network platform_default \
  minio/mc alias set minio http://minio:9000 minioadmin minioadmin

# 同步到备份目录
docker run --rm -v /data/backup/minio:/backup \
  minio/mc mirror minio/platform /backup/$(date +%Y%m%d)
```

## 4. 验证与恢复

### 4.1 恢复验证流程（每月至少一次）

```bash
# 1. 创建临时恢复容器
docker run -d --name mysql-restore \
  -e MYSQL_ROOT_PASSWORD=root123456 \
  mysql:8.0

# 2. 导入备份
gunzip < /data/backup/mysql/20260101_020000/platform.sql.gz \
  | docker exec -i mysql-restore mysql -uroot -proot123456 platform

# 3. 验证数据完整性
docker exec mysql-restore mysql -uroot -proot123456 \
  -e "SELECT COUNT(*) as user_count FROM platform.sys_user;"

# 4. 清理恢复容器
docker rm -f mysql-restore
```

### 4.2 恢复步骤（生产）

| 场景 | 操作 | 预期停机 |
|------|------|---------|
| 误删表 | 恢复单库单表 | 分钟级 |
| 数据损坏 | 全量恢复 + binlog 回放到误操作前 | 小时级 |
| 整机故障 | 新机器部署 Docker → 拉取最新备份 → 启动 | 小时级 |

## 5. 存储规划

| 数据 | 每日增量 | 7 天保留 | 30 天保留 |
|------|---------|---------|----------|
| MySQL 逻辑备份（3 库） | ~200MB | ~1.4GB | ~6GB |
| ES 业务日志（ILM 1 天） | ~1GB | **不累积**（ILM 1 天自动删）| **不累积** |
| ES 快照（其他索引） | ~100MB | ~700MB | ~3GB |
| MinIO 文件 | 视使用量 | — | — |

> **重要变更** (2026-06-04): ES 业务日志启用 1 天 ILM 后，**不再占长保留存储**。原表头"7 天 / 30 天"行已不适用，仅供参考。
>
> 建议备份挂载独立磁盘（非 Docker 数据盘），避免磁盘写满影响主服务。

## 6. 注意事项

1. **敏感信息**：备份 SQL 包含密码哈希等敏感数据，备份文件应限制访问权限
2. **锁表风险**：使用 `--single-transaction` 避免锁表，不适用于 DDL 混合场景
3. **磁盘监控**：备份目录磁盘使用率 > 80% 应告警
4. **定期演练**：每月至少一次恢复演练，验证备份文件有效性
5. **Docker 版本**：以上命令基于 Docker 26+，`docker exec` 路径在 Linux 和 Windows WSL2 下通用
6. **生产密码**（2026-06-04 增）：本文档示例密码 (`root123456` / `minioadmin123`) **仅用于开发环境**。生产环境必须从 `.env.prod` 读取（参考 [部署指南 §8.3](部署指南.md)）。
7. **日志 ILM 1 天保留不备份**：业务日志（`platform-logs-*`）由 ILM 1 天清理，**不在 ES 快照范围**。如需长期保存，应在 §2.3 快照脚本中加 `include_global_state: true` + 自定义索引模式。
8. **MySQL 全量备份与 PITR**：当前仅支持全量 + binlog 手动解析（§2.2），未来 M7 韧性阶段可升级为 MySQL Point-in-Time Recovery (PITR) 自动化。
