### 运营后台 500 超时修复（2026-05-29）
- **根因**：`flyway_schema_history` 表被 user 和 ops 模块共用，版本号重叠（V7-V10），导致 ops 模块的 V5/V8/V9/V10 迁移被跳过，数据库缺列缺表
- **手动补列**：
  - `sys_tenant`：`tenant_type`（V8 迁移）
  - `sys_user`：`dept_id`、`post_id`（V5 迁移）
  - `sys_organization`：`short_name`、`full_name`、`legal_person`、`registered_address`、`business_scope`、`tax_number`、`phone`（V4 迁移）
  - `sys_login_log`：`user_type`、`tenant_id`
- **手动建表**：`sys_storage_config`（V9）、`sys_app`、`sys_tenant_app`（V8）
- **代码修复**：`TenantService.createAdmin()` 添加 `userType=1`，`listAdmins()` 添加 `&userType=1` 过滤
- **监控路由不匹配**：`/api/monitor/health` → 后端实际为 `/ops/monitor/health`（待修复）

### 雪花算法 ID 改造（代码已改，待编译部署）
- **背景**：所有实体类使用 `IdType.ASSIGN_ID`（全局配置），但 `sys_dept`/`sys_post` 表 DDL 仍用 `AUTO_INCREMENT`
- **修改文件**：
  - `V4__init_org_tables.sql`：`sys_dept`/`sys_post` 去掉 `AUTO_INCREMENT`，种子数据去掉 `id` 列
  - `Menu.java`：`@TableId` → `@TableId(type = IdType.ASSIGN_ID)`
  - `Role.java`：`@TableId` → `@TableId(type = IdType.ASSIGN_ID)`
  - `OperLog.java(ops)`：新增 `@TableId(type = IdType.ASSIGN_ID)`
- **数据库**：`sys_dept` + `sys_post` 已手动创建并插入 16 条种子数据
